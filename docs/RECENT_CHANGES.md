# История оптимизаций и доработок

## 1. Решение проблемы зависания создания превью при 512 МБ RAM
- **Причина проблемы**: При быстрой прокрутке браузер запрашивал десятки превью параллельно. Полноразмерные фотографии (24–50 МП) декодировались одновременно в нескольких потоках, потребление памяти превышало лимит контейнера 512 МБ, вызывая OOM-kill или застревание пула воркеров Uvicorn. При возврате из Lightbox превью не догружались.
- **Что было сделано на бэкенде**:
  - Введён семафор конкурентности `thumb_semaphore = threading.Semaphore(2)`: тяжелая генерация выполняется максимум в 2 потока параллельно.
  - Мгновенная отдача готовых файлов кэша мимо семафора.
  - Использование быстрого чернового декодирования Pillow `img.draft("RGB", (size*2, size*2))` для JPEG/MPO — снижает расход оперативной памяти при распаковке в 4–8 раз.
  - Принудительный `gc.collect()` после сохранения WebP-миниатюры.
- **Что сделано на фронтенде**:
  - `IntersectionObserver` с ленивой загрузкой миниатюр по мере приближения к экрану (`rootMargin: '250px'`).
  - Автоматический повтор запроса с экспоненциальной задержкой при временных сетевых сбоях.
  - Кнопка ручного перезапуска генерации прямо на карточке фото, если файл не загрузился после нескольких попыток.

## 5. Управление пользователями и видимость альбомов
- **Исправление редактирования пользователей**:
  - Устранено нежелательное автозаполнение формы браузерными менеджерами паролей (Chrome/Safari), из-за которого имя редактируемого пользователя подменялось на `admin`.
  - Добавлен явный режим редактирования с динамическим заголовком («Редактировать пользователя: [логин]»), подсказкой к полю пароля («пусто = без изменений») и кнопкой «Отмена».
  - Поиск данных редактируемого пользователя переведён на безопасное сопоставление в памяти JavaScript.
- **Исправление прав доступа к альбомам**:
  - Добавлена нечувствительность к регистру путей (`Trip GERMANY` и др.).
  - Добавлена поддержка родительских папок (разрешение на год `2026` автоматически открывает все подпапки).
  - Улучшено сопоставление путей с префиксами библиотек (`lib::path`) и без них.
  - Реализован умный авто-выбор активной библиотеки при входе клиента, чтобы исключить отображение пустого экрана при наличии доступных альбомов в других библиотеках.

## 6. Центрированный макет («Boxed Layout») и PWA для iPad/iPhone
- **Центрирование на мониторах больших диагоналей**:
  - На экранах свыше 1920px интерфейс теперь не расползается к краям монитора: шапка, сайдбар и контент галереи заключены в стильный центрированный контейнер `max-w-[1920px] mx-auto` с аккуратной боковой рамкой и мягкой тенью `shadow-2xl`.
  - Устранена пустая зона между сайдбаром и карточками альбомов: превью примыкают к сайдбару с естественным гармоничным отступом.
  - Полноэкранный просмотр фото (`#lightbox`) сохранен на всю физическую диагональ дисплея.
  - На экранах ноутбуков, планшетов и телефонов макет сохраняет 100% ширину (`w-full`) и стандартную адаптивность.
- **Универсальное веб-приложение (PWA) для iPad / iPhone**:
  - Добавлены мета-теги Apple Web App (`apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `apple-mobile-web-app-title`).
  - Добавлен серверный маршрут `/manifest.json` с поддержкой запуска в автономном режиме `standalone`.
  - Возможность вынести ярлык галереи на домашний экран iPad/iPhone через меню Safari «Поделиться» → «На экран "Домой"»: галерея открывается как нативное приложение без рамок и адресной строки браузера.

## 7. Поддержка воспроизведения видео и видеобиблиотек
- **Глобальный фильтр контента**:
  - В верхней навигационной панели галереи размещён глобальный переключатель **[ Все | Фото | Видео ]**.
  - Переключатель работает глобально для текущей активной библиотеки и мгновенно фильтрует альбомы и контент внутри них.
- **Поддержка видеоформатов и контейнеров**:
  - **Нативные форматы** (`.mp4`, `.m4v`, `.webm`, `.mov`): воспроизведение напрямую из хранилища со стримингом через HTTP 206 Partial Content (Range-запросы) для мгновенной перемотки в любых браузерах (включая Safari/iOS).
  - **Архивные контейнеры** (`.mkv`, `.avi`, `.wmv`, `.flv`, `.mts`, `.m2ts`, `.ts`, `.3gp`): конвертация по запросу в фоновом режиме через FFmpeg в кэш (1080p Web-Ready H.264/AAC). Повторное открытие происходит мгновенно из кэша.
- **Интеллектуальные миниатюры и постеры**:
  - **Приоритет постеров**: если рядом с видеофайлом лежит файл изображения с тем же именем (`video.mp4` и `video.jpg` / `.png` / `.webp`), он автоматически используется в качестве обложки видео.
  - **Исключение дублей**: файл-постер автоматически скрывается из списка независимых фотографий, предотвращая дублирование в альбоме.
  - **Извлечение кадра через FFmpeg**: при отсутствии файла-постера превью извлекается ровно на **4-й секунде** (или в середине ролика, если длительность менее 4 секунд) и сохраняется в WebP (400px и 1200px).
  - **Бейдж длительности**: на миниатюрах видео в сетке отображается бейдж с иконкой воспроизведения и хронометражем (например, `▶ 03:45`).
- **Плеер и технические метаданные**:
  - В лайтбоксе (просмотрщике) интегрирован HTML5-видеоплеер. При переключении кадров стрелками или закрытии воспроизведение автоматически останавливается.
  - В боковой информационной панели (EXIF) для видео отображаются длительность, разрешение, видео- и аудиокодеки, контейнер, размер и дата.
- **Интеграция в предгенерацию кэша и Docker**:
  - Создание миниатюр для видео включено в фоновую задачу предгенерации кэша в панели администратора.
  - В `Dockerfile` добавлен пакет системного `ffmpeg`.
